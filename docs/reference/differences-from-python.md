# Differences from Python

Programs in this language are valid Python syntax and mostly read the way Python does. This page
lists every place where the same code means something different, or where Python code is rejected,
so that nothing surprises a Python programmer twice. Each row links to the rule and gives the
reason in a line.

## What a program means

| Python | Here | Why |
| --- | --- | --- |
| `b = a` makes two names for one list | `b = a` moves an array, list or struct; `a` cannot be used afterward | No garbage collector; ownership decides when memory is freed. [Moves](values-and-references.md#moves) |
| A function can change any list passed to it | Parameters are read-only unless declared `InOut[T]` | The compiler must know what a call can change to prove arrays never alias. [Parameters](values-and-references.md#parameters) |
| An iterator's `__next__` changes it and raises `StopIteration`; `for` calls `__iter__` first | `__next__` is written `def __next__(self: InOut[Self]) -> Raises[T, StopIteration]`; `for` calls it on the iterator itself, without `__iter__`, and the body cannot change or move the iterator | Raising is how any Baryon function says it has no value, and borrowing the iterator lets a loop over a variable leave it usable. [Iterators](syntax.md#iterators) |
| A context manager's `__enter__` returns `self`, and `__exit__(self, exc_type, exc, tb)` sees the error and may swallow it | `__enter__` is written `def __enter__(self: Owned[Self]) -> Self`; `__exit__(self)` takes nothing else and cannot swallow an error; the name after `as` cannot be moved or reassigned in the block | A method returns `self` only when it owns it, and errors are handled by `try`, where the reader sees them. [`with` and context managers](syntax.md#with-and-context-managers) |
| `int` has no size limit | `int` is a 64-bit integer; sized types such as `i32` and `u8` exist | Fixed widths are what fit in a register. [Numbers](types.md#numbers) |
| `float32` and `float64` mix silently in NumPy | Mixing widths is an error until converted with `f64(x)` | Precision never changes without a visible conversion. [Number mixing](types.md#number-mixing) |
| `1.0 / 0.0` raises `ZeroDivisionError` | `1.0 / 0.0` is infinity, as in IEEE 754 and NumPy | Numeric code expects IEEE results. [Numbers](types.md#numbers) |
| `(-8.0) ** (1 / 3)` is a complex number, and `math.sqrt(-1.0)` and `math.log(0.0)` raise `ValueError` | Float `**` and the `math` functions give IEEE 754 results, as NumPy does: `(-8.0) ** (1 / 3)` and `sqrt(-1.0)` are NaN, `log(0.0)` is `-inf` | The same rule as float division by zero: numeric code expects IEEE results, and a float never turns into a complex number. [Math functions](arrays.md#math-functions) |
| `print` of a class instance writes `<Point object at 0x…>` unless the class defines `__repr__`; inside a list or tuple an enum member is `<Phase.GAS: 3>` | A struct prints as a dataclass does, `Point(x=1.0, y=2.0)`, and an enum member prints `Phase.GAS` everywhere | Every struct is a plain value, as a dataclass is, and the compiler keeps an enum member's position, not its value. [`print`](syntax.md#what-print-writes-for-each-value) |
| `z / 0j` and `0j ** -1` raise `ZeroDivisionError` | They give IEEE 754 results, as NumPy does: `(1+1j) / 0` is `inf+infj`, `0j ** -1` is `nan+nanj` | The same rule as float division by zero. [Complex numbers](types.md#complex-numbers) |
| `True + 1` is `2` | `bool` is not a number; that is an error | [bool](types.md#bool) |
| Any value can be a condition: `if items:` | Conditions must be `bool`: `if len(items) > 0:` | A condition should not depend on a rule the reader has to remember. [bool](types.md#bool) |
| A variable can change type: `x = 1` then `x = "one"` | A variable keeps the type of its first value | One name meaning two things is a common bug in long code. [Type inference](types.md#type-inference) |
| `a[-1]` and `a[i]` with `i = -1` both read the last element | `a[-1]` reads the last element; a negative index computed at run time panics | In a stencil, `u[i - 1]` at `i = 0` is a bug, not a wrap-around. [Indexing](arrays.md#indexing) |
| `a[0:100]` on a 10-element list gives 10 elements | A slice past the end panics, for arrays, lists and `str`s alike | A range that does not fit is usually a bug. [Slicing](arrays.md#slicing), [strings](types.md#indexing-slicing-and-methods) |
| `int("٣")` is 3: `int` and `float` read digits from every script | `int(text)` and `float(text)` read ASCII digits only, and an integer past 64 bits raises `ValueError` | Numbers in data files are ASCII, and `int` has 64 bits. [Decision 0037](../decisions/0037-reading-numbers-from-text.md) |
| A slice of a list is a copy; a NumPy slice is a view | An array slice is a view, and cannot be bound to a name in version 0 | A named view would be a stored borrow. [Slices](values-and-references.md#slices) |
| `sum` of an empty list is the integer `0`; `min([1.0, nan])` is `1.0` but `min([nan, 1.0])` is `nan`, and `sorted` leaves NaNs anywhere | `sum` gives the element type, so an empty `list[f64]` sums to `0.0`; `min` and `max` are NaN when any element is NaN, and panic on an empty list; `sorted` puts every NaN last | A value's type never depends on its length, and a NaN never hides depending on where it sits. [Lists](types.md#lists) |
| After `for name in names:`, `name` holds the last element | When the elements are not copied, such as `str`s or lists, reading `name` after the loop is an error until it is assigned again; a number keeps its last value | The loop variable borrows each element; keeping one would be a hidden copy. [Loops over collections](values-and-references.md#loops-over-collections) |
| A list can hold values of different types | `list[T]` holds one type | Values of one type are stored contiguously, with no boxing. [Lists](types.md#lists) |
| Any hashable value is a `dict` key, floats included, and `d[k]` for a missing key raises `KeyError` | Keys are integers, `bool`, `str`, enums and tuples of them; a missing key panics | A float key that misses by rounding is a silent bug. [Dictionaries](types.md#dictionaries) |
| Exceptions unwind, and any function may raise | A function that can fail says so with `Raises[T, E]`; errors are return values | Failure is visible in signatures and costs one branch. [Errors](errors.md) |
| `sys.exit` raises `SystemExit`, which a `try` can catch | `sys.exit` ends the program at once; nothing catches it | It is not an error a caller can handle, and errors are values here. [Exit status](files-and-processes.md#exit-status) |
| `os.environ[name] = value` changes the program's environment | The environment is read-only | Changing it while another thread reads it is a data race in the C library, and `prange` loops run on several threads. [Environment variables](files-and-processes.md#environment-variables) |
| `subprocess.run("ls -l *.dat", shell=True)` hands a line to a shell | `subprocess.run` takes a `list[str]` and has no shell | A shell splits a file name with a space and lets a value become a command. [Running a program](files-and-processes.md#running-a-program) |
| `result.stdout` is `None` when output was not captured, and a timeout raises `TimeoutExpired` | `stdout` and `stderr` are `""` when not captured, and a timeout raises `OSError` with the kind `TIMEOUT` | A field has one type, and one error type covers every failure of the operating system. [Running a program](files-and-processes.md#running-a-program) |
| `sys.stdout = log` sends every later `print` to `log` | `sys.stdout`, `sys.stdin` and `sys.stderr` cannot be assigned; pass the file: `print(..., file=log)` | A module has no variables, so no function's output can be redirected from far away. [Standard streams](files-and-processes.md#standard-streams) |
| `print` to a closed pipe raises `BrokenPipeError`; `input()` raises `UnicodeDecodeError` on a byte that is not UTF-8 | A closed pipe ends the program quietly, as it ends a C program, and `input()` reads the byte as U+FFFD | `print` to standard output never raises, and `input` raises only `EOFError`. [Standard streams](files-and-processes.md#standard-streams) |
| Every failure is an exception and can be caught | Bugs such as an index out of range panic, and panics cannot be caught | A caught bug is an ignored bug. [Panics](errors.md#panics) |
| `assert` is removed by `python -O` | `assert` is checked in every build | [Syntax](syntax.md#statements) |
| Classes have inheritance and reference semantics | A class is a struct, an error type or an enum: a value type with no inheritance. Types share behavior through traits | Inheritance would make struct sizes unknown and method calls indirect, which stops arrays of structs being contiguous and loops vectorizing. [Decision 0015](../decisions/0015-no-class-inheritance.md) |
| The order of a class's attributes does not matter | A struct's fields are stored in declaration order, so the order can change its size through padding | Arrays of structs are shared byte for byte with C, NumPy and file formats. [Field layout](types.md#field-layout) |
| A default such as `history: list[f64] = []` is created once and shared by every call that leaves the argument out | A default is evaluated afresh at each call that leaves the argument out | A shared mutable default is a well-known bug, and shared state would race in parallel loops. [Default parameter values](types.md#default-parameter-values) |
| Top-level code runs on import; modules have global variables | Only definitions at the top level; the program starts at `main` | Shared mutable state would race in parallel loops. [Source files](syntax.md#source-files) |
| A second `def f` at the top level silently replaces the first | Each top-level name is defined once per module | A replaced definition is almost always a mistake. [Source files](syntax.md#source-files) |
| `from . import x` imports relative to the current package | Imports always name modules from the package root | An import reads the same wherever the file sits. [Source files](syntax.md#source-files) |
| A leading `_` marks a name private by convention only | A leading `_` makes a name private to its module; importing it is an error | A module's private helpers stay free to change. [Source files](syntax.md#source-files) |
| `numpy.loadtxt` gives a rank-1 array for a file of one row or column and a table otherwise | `Array.loadtxt` gives a table, `Array[f64, 2]`, unless the context asks for `Array[f64, 1]`; a rank-1 result from a table raises `ValueError` | The rank is part of an array's type, so it is known before the file is read. [Text tables](data-files.md#text-tables) |
| `zlib.compress` and `zlib.decompress` take and give `bytes`, and raise `zlib.error` for a corrupt stream or a bad level | They take and give `Array[u8, 1]`, and raise `OSError` with the kind `INVALID_DATA` and Python's message; `compress`'s streams decode to the same data but are not always zlib's bytes | Baryon has no `bytes` type yet, and one error type covers every file and stream it cannot read. [Compression](compression.md#errors) |
| `gzip.decompress` raises `gzip.BadGzipFile`, `EOFError` or `zlib.error` for a bad file, and `gzip.compress(data)` records the current time | `gzip.decompress` raises `OSError` with the kind `INVALID_DATA` and Python's message; `gzip.compress(data)` records the time 0, "none", unless `mtime` is given | One error type covers every file Baryon cannot read, and Baryon has no clock yet. [Compression](compression.md#gzipcompress) |
| `gzip.open(path, "wb")` writes one member as data arrives | It writes a member for every 4 MiB, held in memory until `close()` | Baryon cannot yet add bytes to the end of a file. [Compression](compression.md#gzipopen) |
| `gzip.open` and `lzma.open` take a text mode such as `"rt"` from any expression, any `encoding`, and `errors=` and `newline=`, and give an `io.TextIOWrapper` | A text mode must be a string literal, a text mode in a variable raising `ValueError`; the encoding is UTF-8, another raising `ValueError`; `errors=` and `newline=` are not built; the file is a `gzip.GzipTextFile` or `lzma.LZMATextFile` | The compiler picks the class a call gives from the mode, and Baryon's text is UTF-8 ([decision 0064](../decisions/0064-utf-8-text-from-bytes.md)). [Compression](compression.md#text-modes) |
| `data.decode()` raises `UnicodeDecodeError` for bytes that are not UTF-8, and `encode` and `decode` take any encoding and `errors=` | It raises `ValueError` with the same message; only `encoding="utf-8"` is accepted, another is a compile error, and there is no `errors=` | Baryon has no error subclasses, and its text is UTF-8 ([decision 0064](../decisions/0064-utf-8-text-from-bytes.md)). [Strings](types.md#indexing-slicing-and-methods) |
| `compression.zstd.decompress` raises `ZstdError` for a bad frame | It raises `OSError` with the kind `INVALID_DATA` and Python's message; a frame damaged in more than one way can name a different check | One error type covers every file Baryon cannot read. [Compression](compression.md#compressionzstddecompress) |
| `compression.zstd.compress(data)` writes the C library's frame, with no checksum unless `options` ask for one | It writes Baryon's own frame, always with the content size and a checksum, about 7% larger at the default level and larger still at high levels; `options` and `zstd_dict` are not built | One encoder strategy written in Baryon (decision 0049). [Compression](compression.md#compressionzstdcompress) |
| `bz2.decompress` raises `ValueError` for a stream cut short and `OSError` for a damaged one, and reads blocks in bzip2's old randomized form | It raises `OSError` with the kind `INVALID_DATA` and Python's message for both, and refuses randomized blocks; `bz2.compress`'s streams decode to the same data but are not always the C library's bytes | One error type covers every file Baryon cannot read, and no bzip2 since 1999 writes randomized blocks. [Compression](compression.md#bz2decompress) |
| `lzma.decompress` raises `LZMAError` for a bad file, decodes every filter xz defines, and takes `format`, `memlimit` and `filters` | It raises `OSError` with the kind `INVALID_DATA` and Python's message; blocks with a filter before LZMA2, such as the x86 branch filter, raise `Invalid or unsupported options`, and the three arguments are not built; `lzma.compress` is not built, and `lzma.open` reads only, as bytes or text, decompressing the whole file at its first `read` | One error type covers every file Baryon cannot read; the rest is not built yet. [Compression](compression.md#lzmadecompress) |
| `plt.plot(x, y)` then `plt.savefig("out.png")` draws on a hidden current figure | `byplot` has no current figure, and `plt.plot`, `plt.savefig` and the other state-machine functions do not exist: write `ax = plt.axes()`, `ax.plot(x, y)`, `ax.savefig("out.png")` | The current figure is a module-level variable, which Baryon has none of, since a parallel loop would race on it; a script that uses one fails to compile rather than drawing in the wrong place. [Coming from matplotlib](plotting.md#coming-from-matplotlib), [decision 0046](../decisions/0046-plotting.md) |
| `fig, ax = plt.subplots()` gives a figure and its axes, and `fig, axs = plt.subplots(2, 2)` a grid | `ax = plt.axes()` gives one axes, saved with `ax.savefig`; `fig = plt.subplots(2, 2)` gives a figure that owns its axes, reached as `fig.axes[i]` row by row | A value has one owner, so `fig` and `ax` cannot share a figure: drawing on `ax` would not change what `fig.savefig` writes. [Coming from matplotlib](plotting.md#coming-from-matplotlib), [decision 0046](../decisions/0046-plotting.md) |

## What Python has that version 0 does not

`lambda` and nested functions, generators and `yield`, `async`, `global` and `nonlocal`, `del`
other than `del d[k]`, `*args` and `**kwargs`, star assignment, `:=`, `set` displays, `set` comprehensions,
generator expressions, `try` with `finally` or `else`, `raise ... from`, `for` and `while` with `else`, `with` other
than `with unsafe:`, files and [context managers](syntax.md#with-and-context-managers), decorators other than `@test`, `@bench` and `@layout("C")`, and the `type`
statement. The compiler rejects each with a message; none is silently ignored. Some will come
later; the [Syntax](syntax.md) chapter lists what is accepted. Class inheritance will not come: it
is left out by design (see the table above).

## Names that look like Python's modules

`math`, `random`, `sys`, `os` and `subprocess` are this language's standard library modules, not
CPython's. They follow Python's names where Python has the function, so `from math import sqrt`
reads as expected, but `random` provides counter-based generators such as `Philox` that Python's
module does not. Running a program under CPython therefore needs a small shim library; roadmap
idea I.11 proposes one, to use CPython as a reference for checking the compiler's output.
