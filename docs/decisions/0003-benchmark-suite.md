# 0003. A C++ and Fortran baseline suite in `bench/`, run by a Rust harness

Status: Accepted
Date: 2026-11-06

## Context

The design plan's performance goal is numeric code within 5% of `gfortran -O3`, and its Phase 0
asks for the benchmark suite to exist before the compiler, so there is a baseline to beat. The
suite needs a home, a set of kernels, a way to prove the kernels compute the right thing, and a
way to record times per machine. Rule 4 of `CONTRIBUTING.md` requires a decision record for a new
top-level directory.

## Decision

- **A new top-level directory, `bench/`.** It holds the kernels, the harness and the recorded
  baselines. Benchmarks are neither compiler crates (`crates/`) nor repository automation
  (`xtask/`), and keeping them together means the NPL versions of the kernels can later sit next
  to the C++ and Fortran ones.
- **Eight kernels, each written in C++ and in Fortran:** N-body, Lennard-Jones molecular dynamics,
  a 3D heat stencil, conjugate gradient on a sparse matrix, RK4, Monte Carlo integration, dense
  matrix multiplication and FFT. They are the plan's work package 0.3 and cover the workloads the
  language is for.
- **Plain, single-threaded, IEEE code with no libraries.** The suite measures what a compiler does
  with straightforward loops, because that is what NPL's compiler will be judged on. Both
  versions perform the same operations in the same order on the same input, generated by one
  xorshift64 stream implemented in both languages.
- **Correctness is checked on every run.** Each kernel prints a checksum, and the harness fails if
  the languages disagree beyond a per-kernel relative tolerance.
- **The harness is a `tooling` crate, `bench`, run as `cargo kernels`.** It is written in Rust,
  not shell or Python, so it falls under the workspace's lint, documentation and test rules, needs
  nothing beyond the pinned toolchain and the compilers it measures, and runs the same way on
  macOS and Linux. Compilers come from `CXX` and `FC`.
- **Baselines are JSON files per platform,** `bench/baselines/<os>-<architecture>.json`, recording
  the machine, compiler versions, flags, commit and every run.
- **CI builds and verifies, but does not gate on time.** CI runs the smoke size on Linux and macOS
  to prove every kernel builds and agrees. Shared CI runners are too noisy for a 10% timing gate;
  that gate, against stored baselines on stable hardware, is roadmap item 1.18.

## Consequences

- There is now a number to beat for every workload in the plan, measured on the machine that
  matters, with a check that it measures a correct computation.
- Adding an NPL kernel later only needs a third source file per kernel and a third compiler in the
  harness; the output protocol and baseline format already fit it.
- Every kernel exists twice, so a change to one kernel is two changes that must stay in step. The
  checksum comparison catches drift.
- Plain loops understate what tuned libraries reach. That is deliberate here; library comparisons
  are a separate item (3.10).
- Contributors who run the suite need a Fortran compiler. Nothing else in the repository does, so
  `cargo xtask ci` does not run it.
